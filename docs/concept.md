# sigil-seer-preempt の概念と設計方針

## 位置づけ

Sigil のバックエンド系部品のひとつ。sigil-aegis-waf が「攻撃を防ぐ盾」なら、sigil-seer-preempt は「攻撃者の側に立って先に穴を見つける」側を担う。

発想の元は2つある。ひとつは能動的サイバー防御（攻撃を受けてから対処するのではなく、やられる前にやる）。もうひとつは Sigil のセキュリティ方針である ADR 0027「守れない層を無くしたい」。守る側の部品だけでは届かない層を、攻める側の視点で先回りして点検する。

## 名前の決定

2026-11-22 に決定した。

- **seer** ＝ 予見者。魔法の要素を持つテーマ語で、「攻撃が来る前に問題を見通す」役割を表す。
- **preempt** ＝ 先制。能動的サイバー防御の「やられる前にやる」を機能語にした。

なお、当初候補にあった oracle（託宣）は、データベース製品と混同するため不採用とした。

## チームの役割

AI エージェントのチームとして動き、役割を分ける。

- **探索役**: コードを読んで怪しい箇所を探す。
- **検証役**: 見つけた問題が実際に再現できるか確かめる。再現できないものは問題として扱わない。
- **修正役**: 直せるものは修正案を作る。
- **レビュー役**: 修正案を必ず別系統のエージェントが確かめる。作った系統自身は承認者になれない。

## 流れ

探索 → 再現 → Issue 化 → 修正案 → 別系統レビュー → PR。

判断と記録は Issue／PR に残し、人間が後から確認・覆せる形にする。見つけただけで終わらせず、再現の証拠と完了条件を Issue に書いて追跡できる形にする。

## 対象範囲

まず自分たちのリポジトリ（Sigil 本体と関連部品）だけを対象にする。他人のシステムには使わない。

## 担当の配慮

ファジング・脆弱性検証といった語彙や内容は、Codex の自動サイバーセーフガード（cyber_policy）に当たりやすいことが分かっている。そのため、実装・実行の担当は agy（Gemini 系統）と Claude を中心にし、この種の段では Codex を候補から外す。

## 他部品との関係（将来像）

- 発見した問題の傾向は、sigil-argus-observe の監視とつなぐ。監査で見つけた弱点のパターンを、平時の監視の観点に変えていく。
- チームの状態や発見状況は、sigil-orchestra の魔法陣ダッシュボードに表示する。
